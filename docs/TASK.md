# TASK (summary)

## Важно

Этот документ содержит **рабочее summary задания**, а не дословный оригинал формулировки.

## Summary задания

Курсовая работа включает 3 последовательные лабораторные:

1. Построить и экспериментально оценить RAG-систему.
2. Разработать backend-приложение в виде микросервисов.
3. Контейнеризовать и оркестрировать приложение из ЛР2.

На текущем этапе планируется только ЛР1.

### Что требуется для ЛР1

- Автоматический сбор документов (не ручная загрузка нескольких файлов).
- Обнаружение новых/изменённых документов, персистентность, обработка ошибок, защита от дублей, повторяемость сбора.
- Очистка текста, нормализация, чанкинг, метаданные документов.
- Выбор embedding-модели и vector store.
- Retrieval с экспериментами по Top-K.
- Reranking и context filtering с сравнением вариантов.
- Генерация ответа LLM по найденному контексту.
- Корректный отказ при нехватке информации в контексте.
- Ссылки на источники в ответах.
- Оценка по датасету тестовых вопросов.
- Реальные эксперименты, сохранённые результаты и обоснованные архитектурные решения.

### Рекомендации задания

- Желательно не менее 30 оценочных вопросов.
- Категории вопросов: factual, multi-document, contextual, unanswerable.
- Эксперименты по chunking/overlap, минимум двум embedding-моделям, Top-K, reranking, порогам filtering, минимум двум LLM-моделям/режимам и минимум двум prompt.
- Часть рекомендаций допускается заменить альтернативой при корректном обосновании.

### Вес критериев

- Рабочий RAG: 20%
- Автоматический сбор: 15%
- Retrieval pipeline: 10%
- Reranking и filtering: 10%
- Генерация ответа: 10%
- Evaluation: 15%
- Research/experiments: 20%

### Ограничения текущего этапа

- Не реализовывать ЛР2/ЛР3 (микросервисы/Kubernetes).
- Не утверждать непроверенные внешние факты (URL, API-доступность, стоимости, benchmark и т.д.).
- Не считать выбор домена/библиотек/провайдера окончательно утверждённым.
